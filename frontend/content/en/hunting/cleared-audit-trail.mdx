dataSource: "Windows security events (1102) and syslog/Linux (log rotation), with a catalog of maintenance windows"
query: |
  SELECT
    host,
    user,
    channel,
    ts
  FROM security_events
  WHERE event_id = 1102
    AND ts >= now() - INTERVAL '48 hours'
    AND NOT EXISTS (
      SELECT 1
      FROM change_windows cw
      WHERE cw.host = security_events.host
        AND cw.type = 'log_maintenance'
        AND security_events.ts BETWEEN cw.start AND cw.end
    )
  ORDER BY ts DESC;

Anti-forensics is rarely the crime itself; it is almost always the attempt to hide another one. The hunt starts by treating the clearing as evidence and ends by asking what disappeared.

<Callout type="warning" title="Preserve before investigating">Export the remaining channels and the clearing event itself before any retention policy shortens the window. Without that, the timeline cannot be rebuilt.</Callout>

## How to use

Run the query on a daily basis, validate it against the maintenance calendar and treat any out-of-window return as a trigger for the ransomware or malware playbook, according to the scope found.
