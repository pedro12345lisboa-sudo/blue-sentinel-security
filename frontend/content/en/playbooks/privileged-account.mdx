A privileged account created with no matching change is at once a process problem and a possible persistence vector. This playbook separates the two and handles the second without waiting for the first.

<Callout type="info" title="Defensive by default">The check is done with authentication records, the identity catalog, and the ticketing system. No step involves elevating privilege on any machine.</Callout>

## Context

`bs-win-member-added-local-admin` flags entry into an administrative group on Windows, `bs-linux-user-created-uid-zero` catches an account created with UID 0 on Linux, and `bs-linux-sudo-unusual-account` covers sudo grants outside the account's normal pattern. In directory environments, the same pattern appears as addition to protected groups.

## When not to use

An account creation covered by an approved change request and within the described scope closes as a documented exception, with no containment. This playbook applies when the request does not exist, does not cover the time, or does not cover the scope.
