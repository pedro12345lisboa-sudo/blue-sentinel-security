When a user reports phishing, speed matters more than perfect analysis. This playbook starts by validating the report and ends with the vector blocked, the evidence preserved, and the user informed of what to watch for.

<Callout type="info" title="Defensive data only">Triage uses headers, endpoint telemetry, and authentication records. No step involves visiting the malicious address or interacting with the attachment outside a controlled environment.</Callout>

## Context

A human report is the most common and the fastest trigger. The `Phishing_Shortened_URL_Social` rule covers the case where the URL has already circulated in logs, `Office_Macro_AutoExec` flags an attachment with an automated macro, and `bs-win-office-spawned-shell` indicates the workstation has already executed code from Office.

## Playbook boundary

If the campaign indicates mailbox compromise with a forwarding rule, the case also goes through compromised account review, keeping this playbook as the main timeline.
