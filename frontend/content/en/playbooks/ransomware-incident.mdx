Ransomware is the case where containment time weighs more than analysis. This playbook prioritizes cutting the spread and preserving volatile evidence, with recovery anchored to a verified backup copy.

<Callout type="danger" title="No payment and no interaction">No step provides for contacting the actor, negotiating, or paying. The recovery path is always an intact backup copy and a reversal of scope.</Callout>

## Context

`bs-audit-log-cleared` flags classic anti-forensics (`event 1102`), `bs-win-run-key-modified` points to boot persistence, and `bs-net-suspicious-outbound` covers the outbound traffic that usually accompanies prior exfiltration. When the three appear together with a report of renaming, the case is treated as ransomware until proven otherwise.

## Playbook boundary

If the report is only about a renamed file with no telemetry alert, the path is common malware triage until encryption at scope is confirmed. Only indicators with a combination of signals or scope beyond a single isolated file belong here.
