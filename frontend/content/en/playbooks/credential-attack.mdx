This playbook kicks in when the `corr-brute-force-sequence` correlation closes a sequence of failed logons detected by `bs-auth-failed-logons` (Windows) or `bs-linux-ssh-failed-logons` (Linux). It covers direct brute force and password spraying, in which the attacker tries a few common passwords against many accounts.

<Callout type="warning" title="Defensive boundary">Everything below uses only authentication data and defensive administrative actions. No step involves testing passwords or running offensive tools.</Callout>

## Context

Spraying is rarely detected on an individual account, because each account receives only one or two attempts. The correct reading is by source and by time window, which is exactly what the correlation delivers. The playbook's first decision is not technical: it is separating a failed attempt from access that was actually granted.

## When not to use

If there is no correlation and only a handful of isolated failures from a known account, the path is the identity support flow, not this playbook. Only alerts with a confirmed sequence or a suspected compromised account belong here.
