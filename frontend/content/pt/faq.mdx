## Os eventos do laboratório são reais?

Não. São eventos sintéticos, gerados para demonstração. Não existe telemetria real de máquina nenhuma nem dado de produção em qualquer etapa do fluxo. O aviso de uso ético aparece na entrada do laboratório.

## Posso usar o laboratório para testar ataques?

Não. O conteúdo aqui é estritamente defensivo e educacional. Não há payloads ofensivos, e nada deve ser usado contra sistema que você não possui ou não tem autorização para testar.

## Com que tecnologias você trabalha?

O repositório usa Next.js e TypeScript no frontend, FastAPI e Python no backend, PostgreSQL e Redis para dados, Docker Compose para orquestração e C++20 no agente em construção. A lista completa está em [Competências técnicas](/about).

## Como os projetos são documentados?

Todo case study segue o mesmo formato: Problema, Contexto, Solução, Arquitetura, Decisões técnicas e por quê, Desafios, Resultados, Aprendizados e Links. Resultados não medidos ficam como `[MÉTRICA MEDIDA]`.

## Encontrei uma vulnerabilidade. O que faço?

Use a página de [Segurança](/security) ou escreva para `security@blue-sentinel.local`. Relato responsável, com prazo de resposta declarado. Não há programa de bug bounty: é um portfólio pessoal.

## Posso contribuir?

Sim. Abra uma issue no repositório com a proposta; se for alteração de regra ou de detecção, inclua o log de exemplo que você usou para validar.

## Por que parte do site está em placeholder?

Porque inventar número, emprego ou certificação é pior do que deixar em aberto. Os placeholders marcam exatamente o que precisa ser preenchido com dado real antes de publicar.
